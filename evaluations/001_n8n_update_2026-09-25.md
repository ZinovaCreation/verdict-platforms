## Executive Summary

n8n published 189 security advisories for the `n8n` package in the trailing window (2025-09-25 → 2026-09-25), 175 of which carry CVE IDs, including 23 rated Critical and a CVSS 3.1 maximum of 10.0 reached by four CVEs (CVE-2026-21858, unauthenticated file access fixed in 1.121.0 on 2025-11-18; CVE-2026-25055; CVE-2026-42231; CVE-2026-54309). One is listed in the CISA KEV catalog: CVE-2025-68613 (expression-injection remote code execution, CVSS 3.1 9.9), with fixes released on 2025-11-19, a vendor advisory on 2025-12-19 and KEV addition on 2026-03-11 (82 days after the advisory; FCEB due date 2026-03-25). The Layer 0 total moves from 35/85 (Tier C) to 46/85 (Tier B), a change of +11: R falls from 5 to 3 on the CVE count, the maximum severity, an Execute Command node CVE addressed by a default change rather than a code fix, and recurring expression-, Python- and task-runner-sandbox escapes, and T falls from 6 to 4 on 9 advisories published more than 60 days after their fixes, while V (+4), D (+10) and C (+1) rise on documentation the migrated prior record did not cite — a sub-processor list dated 2026-09-22, a DPA with Standard Contractual Clauses, per-category retention and no-training statements, a SOC 2 report for enterprise customers with a public SOC 3 report, and task runners enabled by default since 2.0. Since the 2026-04-22 batch every advisory has been published within 30 days of its fix, and 144 of 188 measurable advisories in the window were published no later than one day after the earliest fixed release.

## Contextual Analysis

The volume on record reflects a publication practice as much as a defect rate. n8n publishes advisories in batches aligned with its release train — 24 publication dates in the window, and a fortnightly cadence from July 2026 (07-08, 07-22, 08-05, 08-19, 09-02, 09-03, 09-16) — and states CVSS 4.0 as its primary score. 95 advisories carried a GitHub-assigned CVE ID when read; 78 were published without one and later received a CVE ID from VulnCheck as CNA (CVE records published 2026-06-22 → 2026-09-16), which the repository advisory pages do not display; JFrog assigned two further CVEs to its own findings without a repository advisory. A reader counting CVE IDs on n8n's repository pages alone would reach 95. The 16 advisories published on 2026-09-16 had no CVE ID on the update date and are recorded without being counted.

CVE-2025-68613 is the only n8n entry in the KEV catalog. Fix releases shipped on 2025-11-19 (1.120.4, 1.121.1) and 2025-11-24 (1.122.0); the advisory followed on 2025-12-19; CISA added the CVE on 2026-03-11, 112 days after the first fix release and 82 days after the advisory, with an FCEB due date of 2026-03-25 and ransomware use recorded as Unknown (https://www.cisa.gov/known-exploited-vulnerabilities-catalog). Censys reported more than 100,000 potentially exposed instances in late December 2025, as reported by SC Media (https://www.scworld.com/news/cvss-9-9-rce-vulnerability-in-n8n-potentially-impacts-more-than-100k-servers). Public exploit code chaining CVE-2026-21858 (unauthenticated file read, fixed in 1.121.0 on 2025-11-18) with CVE-2025-68613 was published on 2026-01-07, the day of the CVE-2026-21858 advisory (https://github.com/Chocapikk/CVE-2026-21858). The report records these dates and intervals and draws no inference about the reasons for them.

The Structural-issues score rests on the vendor's own descriptions. Two of n8n's advisories state that additional exploits in expression evaluation were identified and patched following CVE-2025-68613; JFrog's write-up describes a bypass of the hardened expression sandbox through the JavaScript `with` statement, which let an identifier the AST checks treated as harmless resolve to the Function constructor, with code execution on n8n's main node; and one 2026-05-13 advisory is titled as a patch bypass of an earlier XML-node fix. The structural responses in the same window are also on the record: n8n 2.0 moved Code-node execution to task runners in secure mode by default, removed the Pyodide-based Python node, disabled Execute Command and Local File Trigger by default and restricted environment and file access; SSRF protection arrived in 2.12.0 as an opt-in control; external runners, a distroless image and AppArmor guidance are documented. The 2026-07-22 advisory GHSA-hx4h-vr3m-45vh refers to a VM expression engine; the public record read here does not state whether expression evaluation has moved off the main process.

In January 2026 Endor Labs reported malicious npm packages posing as n8n community nodes that captured OAuth tokens entered into their credential forms and sent them to an attacker-controlled host; npm removed several packages, one tracked as GHSA-77g5-qpc3-x24r (https://www.endorlabs.com/learn/n8mare-on-auth-street-supply-chain-attack-targets-n8n-ecosystem). The packages were third-party, not n8n artifacts, and no compromise of n8n's own packages, organization or build pipeline appears in the sources read, so `supply_chain_compromise_12mo` is false. The episode bears on C because community nodes run with the n8n process's privileges, as the researchers note; GHSA-fmmv-p585-7c8x (2026-09-16) records a bypass of community-package install validation in queue-mode deployments.

Capital events in the window did not change control. The Series C (2025-10-09) was led by Accel with NVentures and T.Capital as corporate investors, and SAP's strategic investment (2026-05-12) came with a commercial agreement to embed n8n in SAP's Joule Studio. n8n GmbH remains the operator.
